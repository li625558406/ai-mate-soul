# AI Mate Soul 前端界面重设计

- 日期：2026-09-09
- 状态：已确认（用户逐节确认布局方案 C 与三块设计稿）
- 范围：仅 `public/index.html` 前端重写，不改任何后端 API 与服务

## 1. 背景与问题

现有界面为"左侧 300px 侧边栏 + 右侧聊天区"，存在六个核心问题：

1. **身份配置混进主界面** — User ID、你的名字这类设置项常驻侧边栏最顶部。
2. **侧边栏是大杂烩** — 选角色、看状态、facts、8 个功能按钮、清除记录全部纵向堆叠，无信息分层。
3. **状态区信息过载且重复** — 8 张卡片 + 3 条进度条，"心情"出现两次（stMood / stEmotion），好感度既有卡片又有进度条。
4. **facts 埋在中间** — 有情感价值的内容被挤在小字区域。
5. **功能入口双份** — 朗读/日记/导出在侧边栏功能面板和输入栏各出现一次。
6. **数值反馈挤在一行** — 好感/XP/情绪/天气/忙碌全部塞进侧边栏一行小字，权重不分。

## 2. 目标与决策

- **高可用、使用简单、功能清晰**；状态数据全部保留、重新分层组织。
- **手机与桌面两端并重**，各自精心设计。
- **视觉风格：暖调陪伴风（方案 B）** — 奶油暖底 + 珊瑚粉主色 + 柔和投影，匹配"AI 伴侣"定位。
- **信息架构：角色主页中心（方案 C）** — 主页承载角色状态总览与功能入口，聊天从主页一键进入。

## 3. 视觉规范

```
--bg:        #fdf8f5（页面底，可叠 #fff7f0→#fdeef2 微渐变）
--surface:   #ffffff
--border:    #eadfd8
--text:      #5a4a42（主文字，暖深棕）
--text2:     #b08a80（次要文字）
--accent:    #ff6a88（珊瑚粉主色）
--grad:      linear-gradient(135deg, #ff9a8b, #ff6a88)（主按钮/头像/强调）
--red / --green / --yellow / --orange：保留语义色，色相微调偏暖
```

- 气泡：AI = 白底柔投影；用户 = 珊瑚粉渐变白字；主动消息 = 白底粉色描边。
- 圆角加大（卡片 14px、气泡 16px、按钮 12px），阴影统一为低透明暖色投影。
- 用户可见文案保持简体中文。

## 4. 信息架构（三区）

```
主页（手机默认页 / 桌面左栏）
 ├── 角色信息卡（头像、名字、性别年龄、关系阶段、等级、相识天数、心情徽章）
 ├── 状态总览（好感度条+数值 / 等级经验条 / 心情双向条 / 互动数据：天数·次数·人生阶段）
 ├── 「💬 开始聊天」主按钮
 ├── 功能宫格（单行 3 项）：日记、纪念日、视频
 ├── facts 展示区「♥ 她记住你的事」（标签流，给足空间）
 └── 底部操作行：切换角色 / 设置 / 我的信息

聊天页（手机全屏 / 桌面右栏）
 ├── 顶栏：←返回（仅手机）· 头像 · 名字 · 状态徽章 · ☎语音通话
 ├── 消息流顶部浮层：API 未配置横幅 / 忙碌倒计时条 / 冷战提示
 ├── 消息流：user/ai/proactive/photo/video/system 气泡 + <thought>独白折叠
 │    └─ 数值反馈胶囊贴在对应 AI 消息下方（好感±、xp、LEVEL UP、心情±、情绪、雷区）
 └── 输入栏：输入框 / 发送 / ♪朗读（仅三个元素）

弹层（全部保留现有功能）
 ├── 设置：4 组 API 配置 + 数据管理（导出/导入 .soul/清除聊天记录）
 ├── 我的信息：User ID、你的名字
 ├── 切换角色：角色卡片列表 + 角色详情
 └── 语音通话 overlay / 日记面板 / 纪念日面板 / lightbox
```

### 关键重组决策

| 原位置 | 新位置 |
|---|---|
| User ID / 你的名字（侧边栏顶部） | 「我的信息」弹层 |
| 8 个功能按钮 | 3 个高频（日记/纪念日/视频）进主页宫格；API 配置、导入/导出、清除记录进「设置」；朗读进聊天输入栏 |
| 状态 8 卡片 + 3 条 | 主页状态总览：进度条化 + 数值，"心情"两卡合并为一个心情徽章 + 一个双向心情条 |
| 每条消息 meta（侧边栏一行字） | 胶囊贴到对应 AI 消息下方；LEVEL UP / 雷区触发用醒目样式 |
| 天气/忙碌 meta | 忙碌 → 消息流顶部倒计时浮层（现状保留）；天气 → 主页角色信息卡内小字 |

## 5. 桌面端适配

- **≥900px**：左栏约 340px（主页内容压缩版：信息卡、状态条、facts、宫格、操作行）+ 右侧聊天区。信息架构不变，主页与聊天同屏共存，避免宽屏两跳。
- **<900px**：单栏；主页与聊天页为两个视图，`开始聊天` 进入聊天、`←` 返回主页。切换用容器显隐（无路由库）。
- 手机端保留 safe-area 适配、禁止双击缩放等现有 PWA 行为。

## 6. 技术实现要点

- 仍为**单文件** `public/index.html`（HTML/CSS/JS 一体），匹配现有 sw.js 缓存策略与部署方式；预计重写后行数相近或略增。
- **JS 逻辑层尽量复用**：所有 `fetch` 调用、Socket.IO 事件、SSE 流解析、语音通话音频管线、busy 倒计时、lightbox 等逻辑不变，只改 DOM 挂载点与 id 对应关系。
- 新增的纯 UI 逻辑：主页↔聊天页切换（手机）、状态渲染函数统一（主页与桌面左栏共用一个 render 函数）、数值反馈胶囊渲染。
- 现有全局变量与函数名（`currentCharacterId`、`sendMessage`、`refreshState` 等）保持，降低回归风险。
- `_scratch` 无关；临时验证文件按全局规则放 `.scratch/`。

## 7. 错误处理

- API 未配置横幅：主页顶部与聊天页消息流顶部均可见，点击直达设置弹层（沿用 `cfgBanner` 逻辑）。
- SSE 断线/错误、TTS 失败、视频任务失败：沿用现有 system 消息提示，样式适配新气泡。
- 无角色数据（空角色列表）：主页显示引导态（"请先在 data/characters 添加角色"）。

## 8. 验证方式

无测试框架，采用手动验证（桌面 Chrome + 手机 HTTPS PWA）：

- 核心流：选角色 → 聊天（SSE 流式/独白/照片）→ 状态刷新 → 日记 → 纪念日 → TTS → 语音通话 → 视频 → 导入/导出 → 设置保存。
- 对抗性用例：
  - 超长文本消息（无空格英文/emoji 连发）不撑破气泡；
  - 未选角色/空角色列表时各按钮不报错；
  - 聊天中途切换角色（SSE abort）后消息不串角色；
  - 连续开关所有弹层，Esc 关闭无残留遮罩；
  - 窗口从宽 resize 到窄（跨 900px）布局正确切换；
  - 断网时发送消息显示连接失败且可恢复。

## 9. 不做（Out of Scope）

- 不改后端 API、Socket.IO 协议、数据结构。
- 不新增功能、不做多语言（保持中文硬编码）。
- 不拆分前端文件、不引入框架/构建工具。
- 照片相册页需要新的照片列表接口，属后续迭代（本次照片仅在聊天流中展示）。
